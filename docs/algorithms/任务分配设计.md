# 任务分配设计（讨论稿）

## 核心问题

任务分配模块要回答三个问题：

1. **谁去哪？** —— UAV-Task 匹配
2. **以什么顺序去？** —— 访问序列
3. **最终去哪降落？** —— 终点决策

这三个问题的组合方式不同，就形成了不同的场景。

---

## 场景矩阵

| 维度 | 变体 | 说明 |
|------|------|------|
| 数量关系 | N ≥ M / N < M | 无人机多于任务（选最优子集）或多于任务（一机多任务） |
| 访问顺序 | 单目标 / 多目标序列 | 一机一目标 or 一机多目标需排序 |
| 返回策略 | 返回起点 / 就近机巢 | 预设基地或预设机巢网络 |
| 约束条件 | 续航 / 载荷 / 时间窗 / 优先级 | 各场景约束组合不同 |
| 优化目标 | 距离 / 风险 / 时间 / 多目标权衡 | 可配置的优化目标 |

### 典型场景

- **场景 A：紧急侦察（一对一）** — 3 架 UAV 待命，1 个火灾目标 → 选最近的 1 架前往
- **场景 B：区域配送（多任务 + 往返）** — 2 架 UAV，6 个配送点 → 每机 3 个任务，返回起点
- **场景 C：跨区调度（多任务 + 就近机巢）** — 3 架 UAV，5 个巡检点 → 完成后飞往最近预设机巢
- **场景 D：优先级混合（带时间窗）** — 紧急 + 普通任务混合，紧急任务有时间窗约束

## 整体架构：三阶段拆分

倾向于把任务分配拆成三个阶段，而不是一个黑盒求解器：

```
输入：UAV 列表 + Task 列表 + 机巢列表 + 策略参数
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    ┌───────┐  ┌────────┐  ┌────────┐
    │ 可行性 │  │ 代价   │  │ 场景   │
    │ 过滤   │  │ 矩阵   │  │ 识别   │
    └───┬───┘  └───┬────┘  └───┬────┘
        │          │           │
        └──────────┼───────────┘
                   ▼
            ┌────────────┐
            │  求解器     │
            │ (算法选择)  │
            └─────┬──────┘
                  ▼
        ┌─────────────────┐
        │  输出：          │
        │  每 UAV 的路线   │
        │  + 降落点        │
        └─────────────────┘
```

### 阶段 1：可行性过滤

先排除不可行的组合：
- 载荷不够的 UAV → Task 排除
- 续航飞不到的 UAV → Task 排除
- 有时间窗但时间上赶不到的排除

过滤完得到一个**可行配对集合**。

### 阶段 2：代价矩阵构建

对所有可行配对计算综合代价。关键问题：**代价怎么定义？**

```
代价 = f(距离, 风险, 优先级, 时间紧迫度)
```

| 思路 | 优点 | 缺点 |
|------|------|------|
| 固定权重 `w1*距离 + w2*风险 + ...` | 简单，可控 | 权重不好定，不同场景应该不同 |
| 分层：先过滤高风险，再优化距离 | 业务语义清晰 | 风险阈值怎么定？ |
| 多目标：输出 Pareto 解集 | 不需要定权重，让用户选 | 实现复杂，用户理解成本高 |
| Agent 根据事件语义自动定权重 | 智能，场景自适应 | 依赖 LLM 判断质量 |

**倾向第四种**——Agent 根据事件语义自动决定权重：
- 火灾侦察 → 风险权重高（不能派 UAV 去送死），距离权重低
- 紧急执法 → 时间权重最高，风险权重低
- 日常巡检 → 距离权重最高，成本敏感

权重由 Agent 在理解事件后设定，而不是硬编码。

### 阶段 3：求解

根据场景特征自动选择算法（策略模式）。

---

## 返回策略

两种返回策略，对算法的影响不同：

**返回起点（闭合路径）：**
```
基地 → Task1 → Task2 → Task3 → 基地
约束：总路程 ≤ 续航
模型：CVRP
```

**返回预设机巢（开放路径）：**
```
基地 → Task1 → Task2 → Task3 → 最近机巢
约束：总路程 ≤ 续航（但终点不固定，需要选择机巢）
模型：OVRP 变体（终点从已知点集合中选）
```

"返回预设机巢"比"返回起点"多了一个决策：**选哪个机巢降落**。
- 方案 A：在求解过程中一起优化（把机巢作为虚拟任务点加入）
- 方案 B：求解后再分配最近机巢

## 求解器设计

```
求解器
├── 场景分析器：根据输入特征判断用哪个算法
├── 算法库：
│   ├── 匈牙利算法（一对一指派）
│   ├── 贪心最近邻（基线，快速出解）
│   ├── Clarke-Wright 节约算法（CVRP）
│   ├── ALNS 自适应大邻域搜索（通用 VRP，Phase 2+）
│   └── ... 可扩展
└── 结果后处理：可行性校验、时间计算、风险汇总
```

### 算法选型决策

```python
def select_algorithm(request):
    n_uav = len(request.uavs)
    n_task = len(request.tasks)

    # 一对一指派
    if n_uav >= n_task and not request.require_sequencing:
        return HungarianSolver()

    # 多任务序列
    if request.return_strategy == "return_to_origin":
        return CVRPSolver()
    else:  # nearest_nest
        return OVRPSolver()
```

初期用简单规则，后期可以根据解的质量、求解时间等动态调整。

---

## 算法实现路线

| 阶段 | 算法 | 场景 | 说明 |
|------|------|------|------|
| Phase 1 MVP | 匈牙利算法 | 一对一指派 | SciPy `linear_sum_assignment`，O(n³) |
| Phase 1 MVP | 贪心最近邻 | 多任务简单序列 | 快速可行解，基线 |
| Phase 2 | Clarke-Wright | CVRP（往返） | 经典 VRP 启发式 |
| Phase 2 | 最近插入法 | OVRP（就近机巢） | 开放路径变体 |
| Phase 3 | ALNS | 通用 VRP/VRPTW | 当前 VRP 领域主流精确启发式 |
| Phase 3 | NSGA-II | 多目标优化 | Pareto 前沿 |

> 规模 <50 架：精确算法和启发式都可以用，不需要 GPU 或分布式求解。

## 与 Agent 的交互

Agent 调用任务分配时，传入场景上下文：

```json
{
  "uavs": [...],
  "tasks": [...],
  "nests": [...],
  "return_strategy": "return_to_origin",
  "objective": "multi",
  "context": {
    "event_type": "fire",
    "urgency": "high",
    "risk_tolerance": "low"
  }
}
```

Python 端根据 `context` 自动调整代价矩阵的权重。

## 待定问题

### 1. 机巢归属模型

- **共享机巢网络**：所有 UAV 共享一个机巢网络，任意 UAV 可降落在任意机巢 → 求解时选择最优机巢
- **固定归属**：每架 UAV 有固定归属机巢，只能回自己的 → 约束更强，求解更简单
- 还是两种都要支持？

### 2. 代价融合方式

- Agent 自动定权重（智能，但依赖 LLM 判断质量）
- 用户/场景配置（可控，但需要用户理解权重含义）
- 还是两种都要支持（默认 Agent 自动，允许用户覆盖）？

### 3. 阶段拆分的粒度

- 三阶段拆开（过滤 → 矩阵 → 求解）：模块化清晰，各阶段可独立测试/替换
- 一个整体求解器：实现简单，但不灵活
- 倾向拆开，但需要确认

### 4. 重调度的触发与策略

- 用户手动触发？
- Agent 自动感知（UAV 故障、新任务插入）？
- 重调度是完全重算，还是基于当前方案增量调整？

### 5. 任务执行顺序的约束

- 是否存在"任务 A 必须在任务 B 之前完成"的前置依赖？
- 是否存在"任务 A 和任务 B 必须由同一架 UAV 执行"的捆绑约束？
