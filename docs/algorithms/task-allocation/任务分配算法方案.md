# 任务分配算法方案 — 四层互补架构

> 版本：v1.0 | 日期：2026-08-30 | 状态：定稿

---

## 一、设计原则

1. **场景驱动**：不同场景的问题结构不同，用最合适的算法处理
2. **多算法互补**：各算法扬长避短，形成完整求解链路
3. **Agent 自适应**：LLM Agent 理解事件语义后自动设定参数，而非硬编码规则
4. **统一接口**：对上层暴露统一 API，底层算法切换不影响调用方

---

## 三、各层职责

### 第一层：匈牙利算法 — 精确指派

**职责：** 一对一匹配，UAV ≥ 任务，无排序需求。

| 项目 | 说明 |
|------|------|
| 算法 | 匈牙利算法（Kuhn-Munkres） |
| 复杂度 | O(n³) |
| 实现 | SciPy `linear_sum_assignment` |
| 解质量 | 精确最优 |
| 典型场景 | 紧急侦察：3 架 UAV 待命，1 个火灾目标 → 选最近的 1 架 |

**代价矩阵构建：**

```
C[i][j] = w_dist · 距离(UAV_i, Task_j)
        + w_risk · 风险(UAV_i, Task_j)
        + w_time · 时间紧迫度(Task_j)

权重由 Agent 根据事件语义设定：
  - 火灾侦察 → 风险权重高，距离权重低
  - 紧急执法 → 时间权重最高
  - 日常巡检 → 距离权重最高
```

---

### 第二层：Clarke-Wright 节约算法 — 构造初始解

**职责：** 为多机多任务场景构造高质量初始可行解，作为第三层的热启动。

| 项目 | 说明 |
|------|------|
| 算法 | Clarke-Wright 节约算法 |
| 角色 | 构造启发式，非最终求解器 |
| 输出 | 可行分配方案（可能非最优，但质量可接受） |

**两种返回策略的处理：**

| 返回策略 | 处理方式 |
|---------|---------|
| 返回起点（CVRP） | 标准 Clarke-Wright，终点固定为基地 |
| 就近机巢（OVRP） | 先用贪心为每个任务选倾向机巢，再退化为 CVRP 求解 |

**热启动机制：**

```
Clarke-Wright 输出的解 → 作为 DE 种群的第 1 个个体
其余个体 → 在 CW 解的基础上随机扰动生成
效果：DE 的初始种群质量高，收敛更快
```

### 第三层：离散 DE + ALNS 双引擎 — 核心优化

**职责：** 通用优化求解层，覆盖所有复杂场景。

#### 3.1 离散差分进化（DE）— 全局搜索引擎

**核心优势：**
- 差分变异机制天然适合大范围探索解空间，不容易陷入局部最优
- 统一基因编码，一套编码覆盖一对一、一机多目标、多机多目标三种场景
- 约束通过罚函数融入目标函数，不需要为每种约束设计专门算子

**统一基因编码：**

```
场景：3 架 UAV，5 个目标

一对一指派：
  基因 = [2, 4, 1]
  解码：UAV1→T2, UAV2→T4, UAV3→T1

一机多目标（含访问顺序）：
  基因 = [2,5 | 4,1,3 | -]
  解码：UAV1: T2→T5, UAV2: T4→T1→T3, UAV3: 无任务

带机巢选择：
  基因 = [2,5 | 4,1,3 | -] + [巢A | 巢B | -]
  解码：同上 + UAV1 降落机巢A, UAV2 降落机巢B
```

**离散映射差分操作：**

```
标准 DE（连续空间）：
  变异：v = x_r1 + F · (x_r2 - x_r3)

离散映射（组合空间）：
  "x_r2 - x_r3" → 提取两个方案的差异（哪些任务分配不同）
  "F · 差异"    → 按概率保留这些差异片段
  "x_r1 + 保留的差异" → 将差异应用到基准方案上

语义：从两个方案的差异中学习，改进当前方案
```

**目标函数：**

```
f(方案) = w₁ · 总路程
        + w₂ · 总风险
        + w₃ · 总时间
        + λ₁ · Σ(时间窗违反量)      ← 罚分项
        + λ₂ · Σ(续航违反量)        ← 罚分项
        + λ₃ · Σ(载荷违反量)        ← 罚分项

权重 w₁-w₃ 由 Agent 根据事件语义设定
罚分系数 λ₁-λ₃ 设为足够大的常数，确保硬约束不被违反
```

#### 3.2 ALNS 自适应大邻域搜索 — 局部精炼引擎

**核心优势：**
- destroy-repair 机制有针对性地重建解的局部结构，局部搜索效率极高
- 算子自适应选择，自动找到最有效的 destroy/repair 组合
- 在 VRP 领域，解质量是工程实践中最稳定的元启发式之一

**算子库设计：**

| 类型 | 算子 | 作用 |
|------|------|------|
| destroy | 随机移除 | 随机移除 k 个任务分配，保持多样性 |
| destroy | 最差移除 | 移除代价最高的 k 个配对，针对性优化 |
| destroy | 相关移除 | 移除地理位置相近的 k 个任务，打散聚集 |
| destroy | 时间窗移除 | 移除时间窗违反最大的配对，修复不可行解 |
| repair | 贪心插入 | 按代价增量最小的顺序逐个插入，快速可行 |
| repair | 最优插入 | 对每个被移除任务尝试所有可行位置选最优 |
| repair | regret-k 插入 | 优先插入"如果不在最优位置插入损失最大"的任务 |

**自适应权重机制：**

```
每个算子维护一个权重 w_i
每轮 destroy/repair 后：
  - 如果产生的解更优 → w_i 增加（被更多使用）
  - 如果产生的解更差 → w_i 保持或降低
  - 定期按权重轮盘赌选择算子

效果：算法自动学习哪些算子在当前问题上最有效
```

#### 3.3 双引擎协作流程

```
输入：UAV 列表 + Task 列表 + 机巢列表 + 策略参数
                    │
                    ▼
          ┌─────────────────┐
          │ Clarke-Wright   │  ← 第二层
          │ 构造初始解       │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 离散 DE          │  ← 全局搜索，跳出局部最优
          │ 种群含 CW 解     │
          │ 迭代 N 代        │
          └────────┬────────┘
                   │ 输出 DE 最优解
                   ▼
          ┌─────────────────┐
          │ ALNS             │  ← 局部精炼，打磨细节
          │ 以 DE 最优解为   │
          │ 起点，迭代精炼   │
          └────────┬────────┘
                   │
                   ▼
            最终分配方案
```

**为什么不只用 DE 或只用 ALNS：**

| | DE 单独用 | ALNS 单独用 | DE + ALNS |
|---|---------|-----------|-----------|
| 全局搜索 | ✅ 强 | ❌ 弱（依赖初始解） | ✅ |
| 局部精炼 | ❌ 弱（后期收敛慢） | ✅ 强 | ✅ |
| 初始解质量影响 | 小 | 大 | 小 |
| 场景适应性 | 统一编码，天然适应 | 需针对场景设计算子 | 互补 |

### 第四层：A\* / D\* Lite — 航迹规划与重规划

**职责：** 为分配方案中的每架 UAV 规划可飞航迹，环境变化时重规划。

| 算法 | 适用阶段 | 说明 |
|------|---------|------|
| A\* | Phase 1-2 | 每次全量计算，实现简单，<50 架规模可接受 |
| D\* Lite | Phase 3 | 增量更新，只计算受影响节点，适合频繁变化 |

**航迹重规划的两层结构：**

```
环境变化
  ↓
┌─────────────────────────────┐
│  第一层：航迹重规划（路径层面） │  ← 优先尝试
│  A* 重跑 / D* Lite 局部调整   │
│  分配方案不变                  │
└──────────┬──────────────────┘
           │ 解决不了（目标不可达）
           ↓
┌─────────────────────────────┐
│  第二层：分配重规划（任务层面） │  ← 最后手段
│  回到第三层，DE + ALNS 重跑   │
└─────────────────────────────┘
```

**多机避碰策略：**

| 策略 | 说明 | 阶段 |
|------|------|------|
| 优先级避碰 | 高优先级 UAV 先规划，低优先级 UAV 避让 | Phase 1 |
| 时间窗避碰 | A\* 搜索加入时间维度，避免同一时间到达同一空间 | Phase 2 |
| 协同矩阵 | 参考赵明方法，通过协同矩阵感知其他 UAV 航迹 | Phase 3 |

## 四、Agent 层设计

Agent 不只是"选算法"，而是**参与求解过程的参数设定**。

### 场景识别与参数设定

```json
// Agent 调用任务分配时传入的参数
{
  "uavs": [...],
  "tasks": [...],
  "nests": [...],
  "return_strategy": "return_to_origin | nearest_nest",
  "context": {
    "event_type": "fire | patrol | delivery | enforcement",
    "urgency": "high | medium | low",
    "risk_tolerance": "high | medium | low"
  },
  "weights": {
    "distance": 0.3,
    "risk": 0.5,
    "time": 0.2
  },
  "solver_config": {
    "de_population": 50,
    "de_generations": 100,
    "alns_iterations": 200,
    "time_window_penalty": 1000
  }
}
```

### Agent 决策逻辑

```
接收事件
  ↓
理解事件语义：
  - "火灾侦察" → 紧急、高风险、距离敏感
  - "日常巡逻" → 低紧急、低风险、成本敏感
  - "跨区配送" → 中紧急、续航约束严格
  ↓
识别场景类型 → 路由到对应算法层级
  ↓
设定参数：
  - 代价权重（距离/风险/时间）
  - 约束类型（硬约束/软约束）
  - 求解精度（快速出解 vs 精细优化）
  ↓
调用求解器 → 返回分配方案
```

### 场景-算法路由表

| 场景特征 | 路由到 | Agent 设定的重点参数 |
|---------|--------|---------------------|
| 一对一指派 | 第一层（匈牙利） | 代价权重 |
| 多任务 + 返回起点 | 第二层 + 第三层（CW → DE → ALNS） | 续航约束、任务序列 |
| 多任务 + 就近机巢 | 第二层 + 第三层 | 机巢选择策略、续航约束 |
| 带时间窗 | 第二层 + 第三层 | 时间窗罚分系数、优先级权重 |
| 紧急 + 普通混合 | 第二层 + 第三层 | 紧急任务的时间权重放大 |

## 五、实现路线

| 阶段 | 内容 | 交付物 |
|------|------|--------|
| Phase 1 MVP | 匈牙利算法 + 贪心基线 + A\* 航迹规划 | 一对一指派 + 简单航迹 |
| Phase 2 | Clarke-Wright + 离散 DE 基础版 + A\* 重跑 | 多任务场景 + 基础重规划 |
| Phase 3 | ALNS + DE 完整版 + D\* Lite + Agent 参数自适应 | 全场景覆盖 + 智能调度 |
