# 任务分配 — 算法选型思考

## 核心问题

任务分配不是一个算法能解决的问题，而是一族问题。关键是：**什么场景用什么算法最合适？**

---

## 讨论过程

### 第一轮：运筹学视角

最初从运筹学/组合优化的框架出发，列出了经典方法：

- 匈牙利算法（指派问题）
- Clarke-Wright / ALNS（VRP 问题）
- NSGA-II（多目标优化）

**遗漏：** 没有覆盖群体智能优化方法（差分进化 DE、粒子群 PSO、蚁群 ACO 等），这些在多无人机协同分配的学术研究中是主流方向。

### 第二轮：统一模型思路

参考赵明博士论文的"统一目标分配模型"，讨论了是否应该用一个统一模型 + 通用优化器覆盖所有场景。

**优点：** 一个框架覆盖所有场景，加新场景只需改约束。
**缺点：** 实现复杂度高，不一定每个场景都能达到最优。

**反思：** 不一定要统一模型。核心应该是"什么场景适合什么算法"，而不是"把所有场景塞进一个模型"。

### 第三轮：场景驱动选型

回归本质——按场景特征匹配最合适的算法。

---

## 思考框架

算法选型应从以下维度出发：

```
1. 问题结构是什么？    → 决定问题类型（指派 / VRP / VRPTW / ...）
2. 规模有多大？        → 决定精确方法是否可行
3. 约束有哪些？        → 决定算法能否处理这些约束
4. 实时性要求？        → 决定可接受的求解时间
5. 项目性质？          → 研究型可以探索前沿方法，工程型优先成熟稳定
```

---

## 场景-算法映射（概要）

| 场景 | 问题类型 | 适合的算法方向 | 选择理由 |
|------|---------|--------------|---------|
| 一对一指派 | 二部图匹配 | 精确算法 | 有精确解，不需要近似 |
| 多任务序列 | VRP 变体 | 元启发式 / 群体智能 | 约束多、解空间大，需要灵活的搜索策略 |
| 带时间窗 | VRPTW | 同上，增加时间窗约束处理 | 时间窗让可行域缩小，需要算法能灵活处理约束违反 |
| 多目标权衡 | 多目标优化 | 多目标进化算法 | 需要输出多个方案供决策 |

**关键洞察：** 不同场景的问题结构不同，没有"万能算法"。但同一类问题（如 VRP 变体）可以用同一个算法框架，通过调整约束和目标函数来覆盖。

---

## 统一的是接口，不是算法

虽然不同场景可能用不同算法，但对外接口应该统一：

- Agent 不需要知道底层用的什么算法
- Python 端根据场景参数自动路由到合适的求解器
- 加新场景时，只需新增求解器实现，不影响上层调用

## 待进一步讨论

1. **具体算法选型** — ALNS vs GA vs ACO vs DE，在我们的场景下哪个更合适？需要对比实验
2. **约束的优先级** — 续航、载荷、时间窗、风险，哪些是硬约束哪些是软约束？
3. **联合优化 vs 分阶段** — 分配和航迹规划是分开做还是统一优化？
4. **算法实现的依赖** — 是否需要引入专业优化库（如 OR-Tools、PyMOO）？
