# 前端技术选型建议

## 技术栈总览

```
前端技术栈
├── 框架：Vue 3 + TypeScript + Vite
├── UI 组件：Shadcn-vue + Tailwind CSS
├── 地图/3D：CesiumJS（vue-cesium 封装）
├── 图表：ECharts（风险仪表盘、数据统计）
├── 状态管理：Pinia
├── AI 对话：初期自搭，后期按需引入 AI Elements Vue
└── 构建/包管理：pnpm + Turborepo（monorepo）
```

---

## 一、UI 组件库：Shadcn-vue ✅ 推荐

| 维度 | 评估 |
|------|------|
| 定位 | Radix Vue + Tailwind CSS，复制粘贴式组件，不锁定版本 |
| 定制性 | 极高——源码在项目里，随意修改 |
| TypeScript | 原生支持，类型完备 |
| 生态 | 2026 年 Vue 3 生态顶流，社区活跃 |
| 上手成本 | 需要熟悉 Tailwind，但团队有 TS 基础问题不大 |

**选型理由：** 系统需要高度定制化的界面（地图面板、调度控制台、风险仪表盘），不是标准后台管理系统。Shadcn-vue 提供基础组件但不限制布局，比 Element Plus / Naive UI 自由度高很多。

### 备选方案对比

| 维度 | Element Plus | Naive UI | Ant Design Vue | Shadcn-vue |
|------|-------------|----------|---------------|------------|
| 核心定位 | 后台管理 | 现代高性能 | 企业级规范 | **高度定制** |
| 上手难度 | ⭐ 极易 | ⭐⭐ 中等 | ⭐⭐⭐ 较难 | ⭐⭐⭐ 需懂 Tailwind |
| 定制化 | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ |
| 设计感 | 中规中矩 | 精致 | 稳重 | **现代、精致** |

## 二、AI 交互组件：AI Elements Vue ⚠️ 按需引入

| 维度 | 评估 |
|------|------|
| 定位 | 基于 shadcn-vue 的 AI 交互组件（对话气泡、打字效果、消息流等） |
| 成熟度 | 较新，社区小，文档刚起步 |
| 依赖 | 绑定 shadcn-vue，技术栈兼容 |
| 实际价值 | 提供 Chat UI 原语，省去搭建对话界面的工作 |

**建议：**

- **初期不引入**——等 Agent 对话交互需求明确后再引入
- 对话界面初期用 shadcn-vue 基础组件自搭，几百行代码即可
- 如果后续对话功能复杂了（多轮、流式、工具调用可视化），再引入不迟

## 三、地图/3D 库：CesiumJS ✅ 核心选型

这是最关键的决策——系统的核心就是"在地图上管理无人机"。

### 地图库对比

| 维度 | Leaflet | Mapbox GL JS | CesiumJS | OpenLayers |
|------|---------|-------------|----------|------------|
| 维度 | 2D | 2.5D/3D | **3D 地球** | 2D |
| 包体积 | ~40KB | ~1MB | ~1.5MB | ~300KB |
| 3D 能力 | 无 | 建筑级倾斜 | **全球级 3D 地形** | 无 |
| 地形渲染 | ❌ | 有限 | ✅ 原生 | ❌ |
| 飞行路径可视化 | 勉强 | 可以 | **原生支持** | 勉强 |
| 空间查询配合 | 一般 | 一般 | **天然契合 PostGIS** | 好 |
| 开源 | ✅ | ❌ 商业 | ✅ 部分付费 | ✅ |
| 国内地图源 | 好 | 受限 | 好 | 好 |
| Vue 生态 | vue-leaflet | 需封装 | vue-cesium | 需封装 |

### 选择 CesiumJS 的理由

1. **无人机飞行需要 3D 空间** —— 高度、地形规避、飞行走廊，2D 地图表达不了
2. **风险评估依赖地形** —— 地面障碍物、禁飞区（建筑物高度）、气象可视化，都需要 3D 地形
3. **PostGIS + Cesium 天然配合** —— PostGIS 存空间数据，Cesium 做 3D 渲染，数据管线顺畅
4. **无人机巡检是 Cesium 的经典场景** —— 大疆等厂商的航线规划工具就是基于 Cesium
5. **开源可用** —— CesiumJS 开源，ion 账号免费额度够开发用

### Cesium 在本项目中的应用场景

| 场景 | Cesium 能力 |
|------|------------|
| UAV 实时位置展示 | Entity API，3D 模型加载（glTF/glb） |
| 飞行路径规划可视化 | Polyline + 动画，支持航线编辑 |
| 风险热力图叠加 | Heatmap / 自定义着色器叠加地形 |
| 禁飞区/地理围栏 | Polygon 实体，支持高度拉伸 |
| 地形分析 | Cesium Terrain，支持坡度、高程查询 |
| 空间查询结果展示 | 与 PostGIS GeoJSON 直接对接 |

## 四、Three.js —— 初期不需要

**结论：Cesium 能覆盖 90% 的 3D 需求，Three.js 作为未来补充。**

| 场景 | Cesium | Three.js |
|------|--------|----------|
| 3D 地球 + 地形 | ✅ 原生 | ❌ 需从零构建坐标系 |
| UAV 模型渲染 | ✅ 支持 glTF/glb | ✅ 更精细 |
| 飞行路径动画 | ✅ 原生 Entity API | 需手写 |
| 风险热力图叠加 | ✅ 原生支持 | 需手写 |
| 地理坐标系 | ✅ WGS84 内置 | ❌ 需自己处理 |
| 自定义粒子/特效 | 有限 | ✅ 强项 |
| 建筑物内部漫游 | ❌ | ✅ |

**引入时机：** 如果未来需要建筑物内部精细化 3D 展示（事故现场室内建模）、或无人机本体精细模型展示，再引入 Three.js 作为补充，形成 Cesium（宏观地理）+ Three.js（微观场景）的组合。
